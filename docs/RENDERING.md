# 浏览器渲染与性能验证

## 旧版的实际渲染路径

1.0.2 的抽奖场景使用 Three.js `CSS3DRenderer`，每张卡片是多个 DOM 节点。CSS 变换可能由浏览器 GPU 合成，不能简单说旧版完全没有使用 GPU；但它没有 WebGL 卡片绘制，仍需维护大量 DOM 样式。星空通过 Canvas 2D 逐帧重画，音乐按钮还存在无效动画循环。

## 当前 1.0.5 的渲染路径

- 默认 `WebGLRenderer` + WebGL2 上下文，创建时请求 `powerPreference: high-performance`。
- 卡片使用 `InstancedMesh`，整面卡片墙只需一次绘制调用；已移除星空装饰。
- 人员文字绘制到单张 CanvasTexture 图集，仅初始化与中奖人员变更时更新；旋转和主题切换不会连续重新上传文字纹理。Canvas 2D 仅用于生成标签纹理，不承担主场景逐帧渲染。
- 背景卡片不创建 DOM；中奖结果保留少量可访问的 DOM 名牌，支持清晰文字与照片。
- 主题改变着色器颜色；高亮和闪烁通过实例属性与着色器完成。
- 全场景使用一个动画循环。隐藏页面时暂停；空闲时最多 30 帧/秒，显卡动画时最多 60 帧/秒；减少动态效果设置下静止后停止连续重绘。
- 像素比上限 1.5；检测为软件渲染时降至 0.75，并限制为 30 帧/秒，避免软件光栅器持续绘制高分辨率画面。
- 无 WebGL2 时使用 CSS3D 兼容模式。兼容模式只少量、低频更新名牌，空闲时停止场景循环。
- WebGL 上下文丢失时暂停显示，恢复后重新上传图集、实例矩阵和状态。

不需要给微服容器增加显卡或 `/dev/dri` 权限，绘制发生在访问应用的客户端浏览器。

## 硬件加速与软件 WebGL

WebGL 是浏览器图形 API，并不保证浏览器一定使用物理显卡。浏览器设置、显卡驱动、远程桌面、虚拟机和图形黑名单均可能导致软件渲染。应用只能请求高性能上下文，不能通过网页绕过浏览器禁用硬件加速的设置。

桌面大屏右侧会显示实际情况：

- `WebGL · GPU 渲染`：浏览器报告的渲染器未识别为已知的软件实现。
- `WebGL · 软件渲染`：检测到 SwiftShader、llvmpipe 等软件渲染器。建议开启浏览器设置中的图形/硬件加速并重启浏览器。
- `兼容渲染`：浏览器不提供 WebGL2。

检测依赖浏览器报告的渲染器字符串，不等同于操作系统级显卡利用率监测。在控制台执行以下只读诊断可查看渲染器、绘制调用数、卡片数、像素比和上下文状态：

```javascript
window.lotteryRenderInfo()
```

Chromium 可同时通过 `chrome://gpu` 检查 WebGL 与硬件加速状态。

## 已验证内容

- 默认显示 12 张大字号 DOM 预览名牌，可翻页；该模式停止连续场景绘制。
- 球体为 119 张实例卡片，1 次绘制调用、1 张文字纹理；鼠标拖动和滚轮缩放已验证。
- 动画空闲时图集版本保持不变，隐藏页面不继续提交帧，上下文丢失后可以恢复。
- WebGL 与禁用 WebGL 两种模式都通过开奖、补抽、结果持久化、主题与设置页流程。

本机自动化 Chromium 使用 SwiftShader 软件 WebGL。这里验证的是渲染架构和功能，没有把软件环境的计时当作真实显卡帧率结论，也不保证每台设备都有固定帧率提升。

## 重跑浏览器测试

需要 Playwright 和可用的 Chromium。在已构建项目根目录执行：

```bash
node scripts/smoke-test.cjs
LOTTERY_TEST_DISABLE_WEBGL=1 node scripts/smoke-test.cjs
```

若 Playwright 或浏览器不在默认位置，可设置 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_PATH`。测试使用临时状态目录和 18888 端口，不更改当前活动数据。
